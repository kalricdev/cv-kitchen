# From verified facts to a complete CV

## Gather only what is missing

Establish the target role and document language. Read an existing CV when supplied.
For tailoring, request the full job posting. Ask one question at a time and wait
for the answer. Do not re-interview facts already provided.

Collect employers, positions, dates, responsibilities, education, skills, and
relevant projects. Ask for evidence when a metric or credential is uncertain.
A real achievement needs no invented number. Record missing information as a gap
outside the final CV.

## Tailor with evidence

Compare required and preferred qualifications with the person's facts. Explain
supported matches and gaps without inventing ATS scores or hiring probabilities.
Preserve the original CV. Emphasize relevant supported work and use the posting's
terminology only when it truthfully describes that work. Do not turn integration
experience into implementation experience or add an unearned qualification.

Write directly in the requested language. Use concise summaries and specific
bullets: what the person did, its context, and a supported result when available.
Review dates, credentials, skill levels, contact details, and claims with the person.

Include Projects when the person provides relevant work: project name, their role,
dates, supported contributions, and an authorized link when useful. Include
Certificates for relevant verified credentials or professional
development: exact title, issuing organization, date, and verification link when
available. Describe a course diploma as a course credential, not a degree. Do not
invent entries to fill these sections; omit either section when empty or irrelevant.

## Deliver the CV

Produce the complete CV first. Follow the bundled ATS checklist for conventional
headings, single-column body text, and readable dates. Generate the requested
submission format when tools support it; default to DOCX or a text-based PDF.
An assistant without document tools returns polished text ready to copy into an
editor. Never require a repository, Python installation, or JSON before delivering.

Default generated documents to burnt-orange accents (#c2410c) on a light background,
with readable dark body text. Use color sparingly for headings and rules; preserve
normal letter spacing and selectable text. Honor the user's submission format and
styling requirements first. Keep decorative emojis in project documentation, not CVs.

Compare exported content with the approved draft. Inspect every page, extraction
reading order, dates, and links when possible. Report actual checks and anything
unverified. Extraction cannot prove factual accuracy or universal ATS acceptance.

Return a short change summary, genuine gaps, and unresolved checks after the CV.
Uploading, emailing, or submitting it requires an explicit instruction.

## Optional continuity

If the person requests structured data, use `master-template.json`. The fictional
`sample-master.json` demonstrates its shape; never reuse its career as theirs.
Keep master facts consistent across language versions and retain separate tailored
copies. JSON is supporting data, not the primary CV deliverable.
